= Claim ledger
:date: 2026-08-01

This ledger distinguishes intentions from evidence. Status terms are:
`hypothesis`, `specified`, `sketched`, `implemented`, `integrated`, `tested`,
`verified`, and `operational`.

[cols="2,1,4",options="header"]
|===
|Claim |Status |Evidence or limitation

|Closed action vocabulary
|implemented
|`src/PhiLam/Action.idr` defines memory reads, sandbox calls, and scheduled
evaluations carrying a `RequestId` and `ReplayPolicy`.

|Evidence-based scheduling normalisation
|verified
|`src/PhiLam/Normalize.idr` is total and returns a `NormalForm` certificate;
only identical adjacent `AtMostOnce` requests construct `Redundant` evidence.

|Derivation trace
|verified
|`RewriteEvidence before after` and `Derivation before after` align every
rewrite by type. `audit` erases that evidence to named dynamic positions.
`normalizationLengthAccounting` proves that the audit length is exactly the
number of removed actions.

|Idempotence
|verified
|`normalizeIdempotent` proves that normalizing a result cannot change it.

|Retention order and absence of invented actions
|verified
|`normalizationPreservesOrder` constructs `Subsequence output input` for every
input sequence.

|Abstract scheduler semantic preservation
|verified
|`normalizePreservesSemantics` proves equal interpretation for every
`SchedulerModel` satisfying its explicit at-most-once idempotence law.

|Pure reference scheduler
|verified
|`src/PhiLam/ReferenceScheduler.idr` implements effective scheduling state and
proves `scheduleAtMostOnceIdempotent` for all request identities and initial
states.

|Reference scheduler coherence
|verified
|`WellFormed` requires unique seen identities and proves their reverse is
exactly the at-most-once acceptance order in the effective schedule. Every
action preserves this invariant, so every execution from `emptyState` is
coherent.

|Reference effect counters
|verified
|`interpretMemoryReadsExactly` and `interpretSandboxCallsExactly` prove that
only the corresponding actions increment each counter and that the final value
is exactly the initial value plus the symbolic action count.

|Attempt conservation
|verified
|`atMostOnceAttemptAccounting` proves that every at-most-once attempt contributes
exactly one unit to either seen-set growth or suppression diagnostics, from any
initial scheduler state.

|Reference scheduler normalization preservation
|verified
|`referenceNormalizationPreservesSemantics` specializes the general theorem to
the executable reference model. The bounded corpus independently checks the
same agreement.

|Suppression diagnostics
|verified
|`AtMostOnceDecision` constructively classifies every attempt as accepted or
suppressed and carries proofs of the membership condition, effective
transition, and exact diagnostic. Diagnostic-list preservation under
normalization is deliberately not claimed; `normalizationDiagnosticAccounting`
instead proves that each recorded rewrite removes exactly one suppression
diagnostic.

|External runtime semantic preservation
|hypothesis
|No external queue or service adapter exists. A future adapter must construct a
lawful model; the reference proof does not assert that an arbitrary scheduler,
LLM API, retry loop, or persistence layer is idempotent.

|Independent Lean normalizer metatheory
|verified
|`formal/lean/PhiLamFormal.lean` reconstructs the calculus in Lean 4 and proves
normal-form production, fixed points, executable/logical normality equivalence,
strict decrease, absence of infinite chains, exact derivation accounting,
confluence, unique reachable normal forms, completeness, and model-parametric
semantic preservation. CI treats warnings, including `sorry`, as failures and
runs `leanchecker` over the compiled environment.

|Idris–Lean correspondence vectors
|tested
|Both implementations check the documented positive and negative vectors and
the same 781-sequence bounded corpus. There is no extraction pipeline or
theorem relating the two source languages, so full implementation equivalence
is not claimed.

|Confluence of the current rewrite system
|verified
|Every derivation preserves `normalize`; any two results reachable from one
input therefore join at its normalized form, and reachable normal forms are
unique.

|Streaming normalization
|verified
|Lean's `streamChunk_append`, `streamNormalize_chunked`, and
`streamNormalize_eq_normalize` prove resumable chunk processing and batch
normalization agree, using one pending action to handle a redundant pair split
across a boundary.

|Confluence after adding more rules
|hypothesis
|The proof covers the current single rule. Every future rule needs termination,
normalization-invariance, and interaction proofs before this status can extend
to a larger calculus.

|Kautz graph topology or “Type 6” semantics
|hypothesis
|The terminology is quarantined by ADR 0002 pending a definition.

|Elixir orchestrator
|hypothesis
|No orchestrator exists on `main`.

|Zig sandbox
|hypothesis
|No sandbox exists on `main`.

|Julia inference engine
|hypothesis
|No inference engine exists on `main`.

|Multi-language integration
|hypothesis
|There are no language boundaries or integration tests.

|Production readiness
|hypothesis
|There is no deployment, release, threat model, or operational evidence.
|===

The executable suite also exhaustively checks all 781 sequences of length zero
through four over a five-action vocabulary for normality, idempotence,
trace/removal accounting, agreement between original and normalized reference
execution, agreement between the execution API and interpreter, and scheduler
coherence. The same corpus also checks exact effect counters, attempt
conservation, and Lean streaming/batch agreement. Additional cases cover
distinct identities, repeatable requests, mixed policies, non-adjacent
suppression, diagnostics, chunk-boundary suppression, and memory/sandbox
counters. These bounded tests supplement the general proofs; they are not their
foundation.

The original generated state is retained by the annotated Git tag
`forensic/gemini-scaffold-2026-08-01` for audit and comparison.
